How this works, in plain language

1 · Background script — the doorman

Adds Read Aloud to the right-click menu. On click it opens the side panel, injects the content script, and saves the sentences for the panel.

entrypoints/background.ts

2 · Content script — the page hand

The only piece that touches the web page. It finds your selection, cuts it into sentences, remembers where each sits, and paints the highlight.

entrypoints/reader.content.ts

3 · Side panel — the music player

React app. Owns the Kokoro voice, makes audio sentence by sentence, plays it, and tells the page which sentence to highlight.

entrypoints/sidepanel/

Privacy: the text travels page → background → panel → voice model, all inside your browser. The only network call is the one-time model download.

Components click to expand

Background script entrypoints/background.ts

Creates the Read Aloud item (only when text is selected). On click: opens the panel first and synchronously (browsers require it), injects the content script via activeTab, asks it for chunks, saves them to storage.session.

PRD Triggering a reading

Content script entrypoints/reader.content.ts

Injected only on demand, never on every site. Splits the selection with Intl.Segmenter, builds a page Range per chunk, answers highlight(i) / clear, and clears the highlight if the panel's connection drops.

PRD Sentence-by-sentence reading and highlighting

Chunker lib/chunker.ts

Pure functions: sentences → chunks of one or two sentences (very short ones merge with the next). No browser APIs, so it is easy to test.

PRD Sentence-by-sentence reading and highlighting

Voice worker + client lib/tts.worker.ts, lib/tts-client.ts

The worker loads Kokoro once (q8, WASM, single thread) and generates audio per chunk. The client reports download progress and maps failures to the two PRD error messages.

PRD States and Boundaries

Player + look-ahead queue lib/player.ts

Keeps ~4–5 chunks generating ahead, plays them back-to-back, exposes play / pause / resume / setSpeed / stop, calls highlight on each chunk start, and discards results from an old readingId.

Where it runs & how to try it

  • npm run dev → Chromium with the extension loaded · npm run dev:firefox → Firefox.
  • npm run build / npm run build:firefox → loadable folders in .output/.
  • Demo video: record in Chrome (assumed): select Reddit text → Read Aloud → download message (cache cleared) → moving highlight → speed → pause/resume.
  • Submission = short demo video + public GitHub repo with a README. No deployment planned.

Failure modes

  • Offline during download → "You seem to be offline, check connection".
  • Model load/generation fails → "Encounter some error, while fetching voice".
  • Slow CPU → play button stays in buffering; the player waits rather than skipping.
  • Selection can't be mapped to the page → it is still read aloud; that chunk simply isn't highlighted.
  • Page can't be scripted (browser pages, stores) → error message, nothing plays.
