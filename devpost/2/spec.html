Core Journey Walkthrough

1. Popup Opened in Chrome or Firefox: Toolbar click mounts the popup. Reads engine and hasWebGpu from browser.storage.local. Implements prd.md > The Core Journey
2. Hardware Probe: On first run without cache, queries navigator.gpu.requestAdapter(). Kokoro default if present; Piper default with warning banner if absent. Implements prd.md > WebGPU Detection & Caching
3. Immediate Persistence: User engine change writes instantly to browser.storage.local with no "Save" button. Implements prd.md > Engine Selection & Switching
4. Single-Engine Audio Generation: When playing, the worker checks if the requested engine is active. If switching, the old engine is stopped and its memory freed before the new engine loads. Implements prd.md > Dual-Engine Audio Playback & Memory Management
5. Shared Playback & Highlighting: Audio chunks from either Kokoro or Piper route through the same shared player, keeping player controls and page highlighting unified. Implements prd.md > Dual-Engine Audio Playback & Memory Management

Dual Engine Specifications

Kokoro TTS Engine

  • Target: High quality, natural neural voice.
  • Optimal Hardware: WebGPU hardware acceleration.
  • Library: kokoro-js + local ONNX Runtime Web WASM.
  • Memory footprint: ~80MB ONNX model.

Piper TTS Engine

  • Target: Fast, lightweight voice on standard CPUs.
  • Optimal Hardware: Standard CPU / WebAssembly.
  • Library: @mintplex-labs/piper-tts-web with built-in WASM phonemizer.
  • Memory footprint: ~60MB ONNX voice model.

Planned Component Architecture

entrypoints/popup/App.tsx

Cross-browser React component rendering the engine selector and warning banner. Binds directly to lib/settings.ts.

lib/tts.worker.ts & Memory Management

Unified worker managing single-model residency in RAM:

  • activeEngine: 'kokoro' | 'piper' | null
  • unloadActiveEngine(): Disposes active engine instance to reclaim WebAssembly memory.
  • loadEngine(engine): Unloads old engine first, then instantiates new engine.
  • generate(text, voiceId, engine): Synthesizes text chunk into playable audio.

lib/player.ts (Shared Player)

Unified playback pipeline: reads active engine preference, feeds chunks to worker, plays audio, and drives page sentence highlights identically for both engines.

Decisions & Learner Insights

Learner Decisions Incorporated

1. Dual-Engine Audio: Both Kokoro and Piper will synthesize and play audio through the shared player.

2. Mutual Exclusion & Memory Conservation: To prevent multiple heavy neural network models from exhausting browser RAM simultaneously, only one engine is active in memory at a time. Switching engines tears down and unloads the old model before the new one loads.

3. Cross-Browser Standard: Standardized on browser.storage.local via WXT to ensure equal functionality in both Chromium and Firefox.
